Why UX/UI

왜 UX·UI 부문인가

저의 강점은 시각 스타일 자체보다, 사용자가 어디에서 멈추는지 파악하고 핵심 가치를 끝까지 전달하는 흐름을 설계하는 데 있습니다.

사용자 정의와 문제 구조화

골프 레슨과 서비스 운영을 병행하며, 사용자가 말하는 불편과 실제 행동 사이의 차이를 직접 관찰했습니다. 이 경험 덕분에 문제를 막연한 아이디어가 아니라 구체적인 사용자 맥락으로 정리할 수 있습니다.

화면보다 흐름 중심의 설계

The Golf Code에서는 단순히 분석 결과를 보여주는 데서 멈추지 않고, 결과 이해 → 원인 해석 → 다음 행동으로 이어지는 흐름을 설계했습니다. 저는 한 장의 화면보다 전체 사용자 여정이 어떻게 이어지는지를 먼저 봅니다.

검증 가능한 UX

순방문자, 요청 수, 베타 테스트, 검색 유입 등 실제 반응을 통해 서비스 구조를 점검해 왔습니다. 감각에만 의존하지 않고, 실제 사용과 반응을 바탕으로 UX를 개선하는 방식에 익숙합니다.

Hackathon Approach

해커톤에서의 UX 작업 방식

문제 정의에서 화면 흐름까지, 빠르게 구체화하는 방식

짧은 시간일수록 화려한 기능보다 문제를 명확히 정의하고, 최소한의 화면으로 핵심 가치를 전달하는 구조가 중요하다고 생각합니다. 저는 이 초기 구조화와 흐름 설계 단계에서 가장 크게 기여할 수 있습니다.

UX WORKFLOW
① 문제 정의 타깃 사용자, 사용 상황, 핵심 불편을 먼저 정리해 팀의 기준을 맞춥니다.
② MVP 흐름 설계 첫 진입부터 핵심 가치 경험, 행동 유도까지 필요한 최소 화면과 흐름을 구조화합니다.
③ 테스트와 개선 이탈 포인트와 혼란 지점을 빠르게 점검하고, 개발 가능한 수준으로 수정안을 반영합니다.

신한 스퀘어브릿지 청년 해커톤에서는 UX·UI 역할로 참여해, 팀의 아이디어를 실제로 개발 가능한 사용자 흐름과 화면 구조로 구체화하겠습니다.

  • 타깃 사용자와 핵심 문제를 빠르게 정의하는 구조화
  • 기획 의도를 개발자와 바로 공유할 수 있는 화면 흐름 설계
  • 짧은 테스트 기반으로 개선 포인트를 찾고 완성도를 높이는 운영 방식
Team Role

팀에서의 역할

UX·UI 주도, 프론트 협업 가능

캡스톤 디자인에서 PL을 맡아 AI학부생, 디자인 담당과 함께 3인 팀을 운영하며 기술 스택 결정, 개발 로드맵 설계, 회의록과 명세서 작성을 주도했습니다. 이 경험을 통해 좋은 결과물은 아이디어 자체보다 팀이 같은 기준과 속도로 움직이게 만드는 구조에서 나온다는 점을 배웠습니다.

해커톤에서는 문제 정의, 사용자 여정 정리, 핵심 화면 구조 설계, 카피 방향 정리, 팀 커뮤니케이션까지 UX 전반을 담당하겠습니다.

Frontend Collaboration

필요 시 프론트엔드 협업도 가능합니다. React, TypeScript, HTML, CSS 기반으로 직접 화면 구현을 해본 경험이 있어 기획 의도를 개발 단계까지 연결할 수 있습니다. 즉, 단순 아이디어 제안자가 아니라 실제 구현을 고려해 UX를 설계하는 사람에 가깝습니다.

문제 정의 사용자 여정 설계 화면 흐름 설계 정보 구조화 카피 방향 정리 팀 R&R 조율 도메인 리서치 빠른 MVP 구현 검증 루프 설계
